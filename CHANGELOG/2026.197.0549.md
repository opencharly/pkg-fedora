# 2026.197.0549 — Remove stale per-repo PR template (stray status-context divergence)

`.github/pull_request_template.md` was added in `2026.188.1054`, before the
git-workflow policy was later centralized onto a single organization-wide PR
template (`opencharly/.github/.github/PULL_REQUEST_TEMPLATE.md` — see
`plugins` commit `bca9193` "docs: centralize branch-protection ownership",
which states the policy explicitly: "single org source ... no per-repo
copy"). The per-repo copy was never swept when that policy landed, so it kept
shadowing the canonical template for every `gh pr create` on this repo — and
its content had drifted stale too, still naming the retired
`charly/claude-validation` status-check context instead of the live
`charly/pr-validator` context that GitHub branch protection on this repo (and
every other OpenCharly repo) has actually required since the harness-neutral
rename.

Deleting the file (rather than patching its content) restores the
single-org-source invariant and lets `gh pr create` fall back to the
already-correct canonical template, closing both the duplication and the
stale-name divergence in one change.
